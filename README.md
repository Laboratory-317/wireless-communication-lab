# Сайт лаборатории беспроводной связи

Статический сайт лаборатории с несколькими вариантами визуальной темы.

Контент ведётся через Markdown-файлы в `content/`. Людям, которые обновляют сайт, не нужно редактировать JavaScript и не нужно писать JSON.

## Где лежит контент

- `content/site.md` - общие настройки сайта и список тем.
- `content/navigation/` - название лаборатории, подзаголовок и порядок вкладок.
- `content/home/` - исследования на главной странице.
- `content/people/` - группы участников и имена.
- `content/students/` - страница для студентов.
- `content/projects/` - проекты.
- `content/patents/` - патенты и РИД.
- `content/publications/` - разделы публикаций.
- `content/media/` - разделы медиа.
- `content/news/` - страница новостей; каждая новость пишется как `##`.
- `content/cv/` - отдельные CV сотрудников в формате `surname_ru.md` и `surname_en.md`.

В каждой папке страницы есть `ru.md` и `en.md`. При изменении контента нужно
обновлять обе языковые версии.

## Формат Markdown

Пишите обычный Markdown.

Страница с разделами:

```md
# Заголовок страницы

## Название раздела

Текст раздела.
```

Страница со списком:

```md
# Публикации

- Международные журналы
- Российские журналы
- Патенты
```

Страница с карточками внутри групп:

```md
# Исследования

## Группа направлений

### Название карточки

Описание карточки обычным текстом.
```

Если вложенные карточки не нужны, можно писать проще: `## Название карточки`
и текст сразу под ним.

Страница участников:

```md
# Участники

### Команда лаборатории

## Инженеры

### Фамилия Имя Отчество

[Ссылка на фото]

Краткое описание должности или роли.

- E-mail:
- Scholar:
- ORCID:
```

## Как добавить новость

Откройте `content/news/ru.md` и добавьте новую секцию `##`:

```md
# Новости

## Заголовок новости

Дата: 2026-08-16

Текст новости обычным Markdown.
```

То же самое добавьте в `content/news/en.md`:

```md
# News

## News title

Date: 2026-08-16

News text in plain Markdown.
```

Новости показываются в том порядке, в котором идут в файле. Поле `Дата:`
можно пропустить.

## Как добавить CV

Создайте два файла в `content/cv/`: `surname_ru.md` и `surname_en.md`.
Например:

```text
content/cv/ivanov_ru.md
content/cv/ivanov_en.md
```

Ссылка на CV из карточки коллектива:

```md
 - CV: [CV](cv.html?person=ivanov)
```

На странице коллектива отдельная строка `CV` не показывается: кликабельным
становится ФИО сотрудника.

## Перевод на английский

Обычная сборка не использует автоматический перевод:

```powershell
node tools/build-content.js
```

Если нужен перевод из `ru.md` в `en.md`, запустите его отдельно:

```powershell
node tools/translate-ru-to-en.js --all --write --if-source-newer
```

Для регулярной работы лучше использовать локальный LibreTranslate:

```powershell
node tools/translate-ru-to-en.js --all --write --if-source-newer --provider libre
```

## Шаблоны Obsidian

Откройте папку репозитория как vault в Obsidian.

Включите встроенный плагин Templates и задайте:

```text
Template folder location: obsidian-templates
```

Шаблоны лежат в `obsidian-templates/`. Их можно вставлять при создании новой
новости или переписывании страницы.

Папку `.obsidian/` не нужно коммитить: это локальные настройки редактора, она
добавлена в `.gitignore`.

## Проверка локально

Сгенерированный файл:

```text
js/lab-content.js
```

Он создаётся из Markdown:

```powershell
node tools/build-content.js
```

Полная проверка структуры сайта:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-theme-showcase.ps1
```

Не редактируйте `js/lab-content.js` вручную.

## Публикация

Запушьте изменения в `main`.

GitHub Pages запустит `.github/workflows/pages.yml`, выполнит
`node tools/build-site.js`, проверит страницы и соберёт публичные файлы в `_site/`.
Служебная документация и исходные Markdown в публичный артефакт не включаются.
Сама публикация по-прежнему происходит только на GitHub Pages.

Для редактирования через браузер достаточно менять Markdown в интерфейсе GitHub:
локальная установка инструментов не нужна. Пошаговая инструкция — в
[`content/README.md`](content/README.md).

## Четыре варианта оформления

- Академический справочник — боковая навигация и книжная типографика.
- Витрина исследований — широкие блоки со схемами и текстом.
- Научный журнал — журнальная шапка и асимметричные колонки.
- Инженерный атлас — техническая сетка и нумерованные блоки.

Адреса в `themes-preview/` сохранены. Сравнение с научными сайтами, обоснование
решений и ограничения описаны в [`state/DESIGN_REVIEW.md`](state/DESIGN_REVIEW.md).

## Что не хранить в репозитории

В репозитории должны быть контент, код сайта и шаблоны.

Не коммитятся локальные и служебные папки:

- `.obsidian/`
- `codex/`
- `themes-preview/*-demo/`
