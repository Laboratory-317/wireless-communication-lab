# Еженедельное обновление Google Scholar

Бесплатный прямой запрос публичных профилей Покаместова и Крюкова. SerpApi,
API-ключи, телефон, сторонние библиотеки и секреты не требуются.

Workflow `Deploy GitHub Pages` в основном репозитории запускается по понедельникам
в 10:23 по Томску (03:23 UTC; GitHub может задержать запуск). Доступен ручной
запуск через Actions → Deploy GitHub Pages → Run workflow на ветке `main`.
Push собирает сайт без обращения к Scholar.

`tools/scholar-profiles.json` задаёт профили и четыре исходных списка публикаций:
классический и Quarto, RU и EN. Синхронизация добавляет записи в раздел всех
публикаций по годам, не изменяя избранные и существующую библиографию.
Начальный год импорта — 2026 (`min_year` в конфигурации): старые работы
намеренно не добавляются, поскольку в профилях встречаются дубли и ошибки
метаданных. Названия с многоточием или словом «учредители» пропускаются
с сообщением в журнале.

Scholar используется только для поиска кандидатов. Python запрашивает
Crossref REST API и принимает запись только при совпадении нормализованного
названия, года и фамилии первого автора. Требуются единственный DOI,
тип journal-article/proceedings-article, название издания и имена/фамилии всех
авторов в метаданных. При нескольких подходящих DOI совпадение неоднозначно:
автоматическая публикация не выполняется. API Crossref доступен без ключа.

Если Crossref не дал полного однозначного результата или недоступен, скрипт
переходит к сайтам журналов и карточкам eLIBRARY. `publication_sources.py`
читает стандартные Highwire `citation_*`, поля PRISM и JSON-LD ScholarlyArticle.
Проверяются название, год, все видимые авторы кандидата в исходном порядке,
название издания и наличие страниц/номера статьи. Сокращённые авторы и
конфликтующие метаданные не принимаются. Поля из разных схем не склеиваются.
DOI не обязателен: для работы без DOI выводится `[Источник](...)` в RU и
`[Source](...)` в EN, с подтверждённым URL карточки.

Поиск источников настраивается в `tools/publication-sources.json`:

- `allowed_hosts`: разрешённые сайты журналов; eLIBRARY разрешена отдельно.
- `publisher_searches`: правила поиска по названию на сайтах журналов. Сейчас
  задан поиск T-Comm на платформе РЦНИ; другие журналы добавляются по мере
  проверки их поисковых форм. В результатах берутся ссылки с совпадающим
  полным названием, а не библиография из поискового сниппета.
- `articles`: необязательные известные ссылки `{ "title": "...", "urls": [...] }`.
  Это ссылки на источники, не ручная подстановка библиографических полей.

Скрипт также использует ссылки из существующих записей, `source_urls` кандидата
и издательские URL из Crossref. С издательской страницы извлекаются ссылки на
eLIBRARY, где принимаются только карточки `item.asp?id=...` и EDN-ссылки.
Поиск по всей базе eLIBRARY без API/авторизации не реализован: карточки
проверяются по найденным или известным ссылкам. Если ресурс закрыт либо на
странице нет поддерживаемых полных метаданных, запись остаётся в pending.
Структура метаданных реальных карточек eLIBRARY пока не проверена из-за
недоступности сайта; поддержка стандартных метатегов проверена HTML-фикстурами.

Перед запросами проверяется robots.txt. Используются только HTTPS и явно
разрешённые домены, максимум 20 запросов к источникам за запуск и пауза 2 секунды
между запросами на один хост. Ошибки и ответы кешируются на время запуска.
Нет обхода CAPTCHA, использования сессионных cookie или ротации прокси.

Библиография формируется из подтверждённых полей любого источника по формату сайта:
`- **Название.** Авторы. *Издание*, vol. 39, no. 16, e70606. 2026. [DOI](...)`.
Страницы оформляются как `pp. 18–26`; номер статьи не обозначается страницами.
Том, номер, страницы и номер статьи добавляются только при наличии метаданных.
Год указывается один раз. Списки авторов с многоточием/et al. не допускаются.
Никаких догадок о полных именах, DOI и отсутствующих полях. Названия сохраняются
на языке найденной записи, автоматический перевод не выполняется.

Неподтверждённые работы сохраняются в `data/scholar-pending.json` с причиной
и повторно проверяются при следующих успешных запусках. Отсутствие статьи в
Crossref само по себе не отклоняет её. В pending записываются попытки обращения
к источникам и причины отказов; парсеры всех издательских сайтов не реализованы.
Ранее добавленные этим скриптом сырые строки со ссылкой `[Google Scholar]`
заменяются проверенной библиографией; при отсутствии подтверждения запись
переносится в pending. Остальные ручные записи не переписываются.
Дубли проверяются по DOI и нормализованному названию. Разные языковые варианты
названий без совпадающего DOI могут потребовать отдельного сопоставления.

На каждый профиль делается один запрос: до 100 последних работ, сортировка
по дате. Старый архив из более чем 100 работ полностью не импортируется.
Перед загрузкой проверяется robots.txt; пагинация и отдельные карточки статей
не запрашиваются. Между профилями выдерживается пауза 5 секунд. Без обхода
CAPTCHA, ротации прокси, авторизации и повторных запросов при блокировке.

При HTTP 403/429, CAPTCHA, запрете robots.txt, отсутствии датированных записей
или изменении разметки Scholar скрипт завершается с ошибкой до записи файлов. Старый
сайт остаётся опубликованным, а ошибка видна в GitHub Actions. Работы без года
пропускаются с сообщением в журнале; исчезнувшие статьи не удаляются. Доступ с
GitHub Actions может отличаться от доступа с компьютера.

После синхронизации существующий workflow собирает и проверяет обе версии
сайта. Только после успешных проверок четыре списка и pending коммитятся в `main`, затем
сайт публикуется в том же запуске. Повторный workflow от коммита бота не нужен.
Для этого Actions получает `contents: write`. Если правила защиты `main`
запрещают push от `GITHUB_TOKEN`, сохранение не пройдёт и запуск завершится
ошибкой; не следует ослаблять защиту без решения владельца репозитория.

Локальная проверка без изменений файлов:

```powershell
python -m unittest discover -s tools -p test_sync_scholar.py
python -m unittest discover -s tools -p 'test_*sources.py'
python tools/sync-scholar.py --dry-run
```
