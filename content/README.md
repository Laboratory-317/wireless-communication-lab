# Как редактировать сайт

Почти весь сайт редактируется обычными Markdown-файлами в этой папке.
Главное правило: структура страницы задается заголовками.

```markdown
# Заголовок страницы

Обычный текст.

## Карточка или раздел

Текст раздела.

### Подраздел

- Список
- Еще пункт
```

## Самый простой способ — через GitHub

1. Откройте нужный файл в папке `content` репозитория и нажмите кнопку редактирования.
2. Скопируйте соседнюю запись как образец, замените текст и ссылки.
3. Обновите парный файл второго языка. Не переводите официальные названия статей
   произвольно: в библиографии допустимо оставлять название на языке оригинала.
4. Посмотрите вкладку Preview и сохраните изменение через Commit changes.
   Изменение в `main` запустит публикацию; изменение в другой ветке сначала нужно
   объединить с `main` через pull request.
5. Откройте Actions. Зелёная проверка Deploy GitHub Pages означает успешную сборку
   и публикацию. Если проверка красная, откройте ошибку: там указаны проблемные
   файл или ссылка. Исправьте их либо восстановите предыдущий текст из History.

Для этого сценария не нужно устанавливать Node.js, Git или редактор кода.
Публикация через GitHub требует доступа на изменение репозитория.

При локальном редактировании в Obsidian после правок запустите:

```powershell
node tools/build-content.js
```

## Перевод RU -> EN

Автоматический перевод не запускается при обычной сборке, чтобы сайт можно было
обновлять без интернета и без дневных лимитов внешних сервисов.

Если нужно подготовить английские версии из русских файлов:

```powershell
node tools/translate-ru-to-en.js --all --write --if-source-newer
```

Для регулярной работы лучше подключить локальный LibreTranslate и запускать:

```powershell
node tools/translate-ru-to-en.js --all --write --if-source-newer --provider libre
```

Адрес локального сервиса задается переменной `LIBRETRANSLATE_URL`, если он не
совпадает со стандартным.

## Основные страницы

- `home/ru.md` и `home/en.md` - главная страница.
- `people/ru.md` и `people/en.md` - коллектив.
- `projects/ru.md` и `projects/en.md` - проекты и гранты.
- `patents/ru.md` и `patents/en.md` - патенты.
- `publications/ru.md` и `publications/en.md` - публикации.
- `media/ru.md` и `media/en.md` - медиа.
- `news/ru.md` и `news/en.md` - новости.

## Иллюстрации и медиа

Файл изображения загрузите в `assets/`, а в Markdown добавьте отдельную строку:

```markdown
![Описание изображения для читателя](assets/research/wireless.svg)
```

Пути к изображениям задаются от корня репозитория. Для страниц используйте
`people.html`, `projects.html`, `publications.html` и другие существующие адреса.
Сайт сам добавляет выбранный язык к внутренним ссылкам.

В `media/ru.md` и `media/en.md` каждый `##` создаёт один материал с изображением
и подписью. Можно добавлять фотографии по тому же образцу. Схемы направлений
находятся в `assets/research/`; их подписи и описания редактируются здесь, в Markdown.

## Коллектив и оформление

Если нет фотографии или контакта, оставьте поле пустым: сайт покажет инициалы
вместо портрета с подписью «Фото пока не добавлено», а пустые контакты — с подписью «Уточняется». Не вводите слово «заглушка».

Названия четырёх оформлений и их описания задаются в `site.md`. Технические
заголовки `## Academic Pages` и другие ключи, как и строки `Ссылка:`, лучше
сохранять: они связывают конфигурацию с существующими страницами. Одна правка
обычного контента автоматически применяется во всех четырёх темах.

## Новости

Новости ведутся прямо в одном файле:

```markdown
# Новости

## Название новости

Дата: 2026-08-24

Текст новости. Можно добавить [ссылку](https://example.com/).
```

Каждый заголовок `##` становится отдельной новостью. Поле `Дата:` можно
добавлять или не добавлять.

## CV сотрудников

CV лежат отдельными файлами:

- `cv/kryukov_ru.md`
- `cv/kryukov_en.md`
- `cv/pokamestov_ru.md`
- `cv/pokamestov_en.md`

Формат имени файла: `surname_ru.md` и `surname_en.md`.

Ссылка из карточки сотрудника задается в `people/ru.md` и `people/en.md`:

```markdown
 - CV: [CV](cv.html?person=kryukov)
```

На сайте отдельная строка `CV` не показывается: кликабельным становится ФИО.

## Чего лучше не делать

- Не редактируйте `js/lab-content.js` вручную. Он создается автоматически.
- Не пишите HTML внутри Markdown, если можно обойтись заголовком, текстом,
  списком или ссылкой.
- Не меняйте файлы в `themes-preview/`, если нужно поменять только текст.

Подписи схем направлений редактируются в `content/research-diagrams/ru.md` и `en.md`. Команда `node tools/build-site.js` пересобирает схемы и сайт.

## Страница для студентов

Файлы `students/ru.md` и `students/en.md` содержат приглашение, три смысловых блока,
список направлений и отдельный блок связи. Сохраните служебные заголовки
`## Направления` / `## Tracks` и `## Первый шаг` / `## First step`.
Заголовок внутри блока связи (`### ...`), текст и подпись кнопки можно менять.

## Проверка и выпуск

Полная локальная сборка: `node tools/build-site.js`. Для проверки открывайте `_site/`
через локальный HTTP-сервер. Эта же команда выполняется на GitHub; новые зависимости
устанавливать не нужно. В pull request запускается **Check site**, а публикация
из `main` выполняется через **Deploy GitHub Pages**. В Settings → Pages источником
сборки должен быть **GitHub Actions**. Само наличие файлов workflow эту настройку
не переключает.

В опубликованных файлах уже есть русский текст, поэтому сайт не остаётся пустым
без JavaScript. Для переключения RU/EN нужен JavaScript; на странице CV без него
показываются оба профиля. Замена корневого `labicon.png` обновит логотип во всех
темах при следующей сборке; круглая обрезка скрывает белые углы исходного изображения.

## Светлая и тёмная тема

Каждый вариант оформления поддерживает светлый и тёмный режим. По умолчанию
«Как в системе» следует настройке браузера/операционной системы и реагирует на её
изменения без перезагрузки. Выбор в шапке сохраняется для всего сайта; возврат к
«Как в системе» снова включает автоматический режим. Подписи переключателя задаются
в `navigation/ru.md` и `navigation/en.md`.

Без JavaScript доступна системная цветовая тема; ручной переключатель скрыт.
Если браузер запрещает сохранение настроек, ручной выбор работает до перехода
на другую страницу. Печать использует светлую палитру.
